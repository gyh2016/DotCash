# DotCash v1 产品与技术方案

## 1. 项目目标
DotCash 是一个以移动端访问为主、同时支持桌面端布局的响应式记账网页应用。首个版本聚焦单用户本地记账，优先完成高频、可闭环的记账流程与统计能力。

## 2. 版本范围（Scope）

### 2.1 本期实现（v1）
1. 账户管理 CRUD（新增、查看、编辑、归档）
2. 记录管理 CRUD（收入、支出、转账）
3. 分类管理（系统默认分类 + 用户自定义分类）
4. 多币种记账（记账币种与入账币种分离）
5. 汇率换算（在线 API 自动换算 + 手动汇率）
6. 预估金额标记与后续实际金额修正
7. 账户初始余额与当前余额自动计算
8. 搜索与筛选（账户、分类、时间、金额范围）
9. 统计面板（本月收入/支出/结余、分类占比、账户按日趋势）
10. 本地数据存储（IndexedDB）
11. 软删除机制
12. 响应式布局：移动端优先 + 桌面适配

### 2.2 本期不实现（Backlog / TODO）
1. 预算管理
2. 多用户/家庭共享账本
3. 登录与云同步
4. 跨币种转账
5. 转账手续费
6. 高级报表与自定义统计维度
7. 本地 JSON 导入导出（放入下一迭代）

## 3. 用户与使用场景

### 3.1 用户画像
- 单人记账用户
- 主要通过手机随手记账，偶尔在电脑上做回顾与整理
- 存在多币种消费或跨境支付场景

### 3.2 核心场景
1. 新建账户并设置初始余额
2. 在指定账户下记录收入/支出
3. 记录外币消费并按汇率估算本币入账
4. 银行实际入账后修正预估金额
5. 通过筛选和统计查看本月资金流向

## 4. 功能需求明细

### 4.1 账户管理
1. 新增账户：名称、类型、默认入账币种、支持入账币种（可搜索多选）、初始余额
2. 账户创建时“支持入账币种”初始值仅包含默认入账币种
3. 账户新增字段：是否允许透支（`allowOverdraft`）
4. 编辑账户：允许修改除系统标识外的所有字段
5. 归档账户：有记录关联时禁止删除，只允许归档
6. 查看账户：展示当前余额、币种、状态（正常/归档）

账户类型建议枚举：
- `cash`（现金）
- `debit_card`（储蓄卡）
- `credit_card`（信用卡）
- `ewallet`（电子钱包）
- `other`（其他）

### 4.2 记录管理
记录类型：
- `income` 收入
- `expense` 支出
- `transfer` 转账（仅支持同币种）

每条记录支持：
1. 选择账户（转账时为转出与转入账户）
2. 选择分类（转账默认无需分类）
3. 输入金额（记账币种）
4. 选择记账币种与入账币种
5. 填写汇率（自动或手动）
6. 设置记录日期时间（支持补记历史）
7. 备注
8. 软删除
9. 记录列表展示该笔记录所属账户（出账账户）
10. 记录列表提供“编辑”“删除（软删除）”操作入口
11. 编辑记录表单组件与新增记录保持一致的交互形态（分区、币种与汇率组件风格统一）
12. 记录列表支持“显示已删除记录”，默认关闭；开启后需明显标注“已删除”
13. 已删除记录仅支持“恢复”操作，不提供编辑或再次删除
14. 记录编辑使用弹窗承载编辑表单，避免打断列表浏览

### 4.3 分类管理
1. 提供默认系统分类（收入类与支出类）
2. 允许用户新增/编辑/归档自定义分类
3. 系统分类不可删除，仅可禁用（可选）
4. 分类展示和下拉选择需按分类名称去重，避免重复项影响录入体验

默认分类建议（初版）：
- 收入：工资、奖金、理财收益、其他收入
- 支出：餐饮、交通、购物、住房、娱乐、医疗、教育、其他支出

### 4.4 多币种与汇率
1. 记账时可选任意币种作为记账币种
2. 每个账户配置“默认入账币种 + 支持入账币种列表”
3. 新增记录时，入账币种从账户支持币种中选择
4. 若交易币种属于账户支持币种，则入账币种固定为交易币种（不可改为其他币种），无需汇率，且该笔记录为实际金额
5. 若交易币种不在支持范围内，则展示汇率组件，并按默认入账币种（可在支持币种中切换）入账，该笔记录为预估金额
6. 自动汇率支持多源兜底（主源失败自动切备用源），仍失败时提示用户切换手动汇率
7. 自动模式下汇率输入框只读，手动模式下可编辑
8. 用户可后续录入银行实际入账金额，并取消预估标记
9. 自动汇率请求过程中展示“正在获取汇率”视觉提示
10. 新增记录时，交易币种和入账币种初始为空；选择账户后再由用户选择两个币种
11. 当交易币种和入账币种都选定后即触发自动汇率加载，不依赖金额输入
12. 选择账户后，入账币种默认赋值为该账户的默认入账币种；字段文案使用“入账币种”
13. 自动汇率加载时，先清空旧汇率，在汇率输入框位置展示加载提示，获取成功后显示新汇率

### 4.5 搜索与筛选
记录列表支持：
1. 按账户筛选
2. 按分类筛选
3. 按日期区间筛选
4. 按金额区间筛选
5. 可按关键字（备注）搜索（建议）
6. 支持重置筛选条件
7. 结束日期不允许小于开始日期

### 4.6 统计面板
1. 本月收入总额
2. 本月支出总额
3. 本月结余（收入 - 支出）
4. 支出分类占比（饼图）
5. 账户余额按日趋势图（折线图）

统计口径：
1. 优先使用 `actualSettledAmountMinor`
2. 若无实际金额，使用 `settledAmountMinor`
3. 按记录发生时间 `occurredAt` 归属统计周期
4. 软删除记录不计入统计

## 5. 核心业务规则
1. 金额统一使用最小货币单位整数存储（如分、cent）
2. 账户余额通过初始余额 + 有效流水计算得出
3. 转账仅同币种，且一笔转账同时影响两个账户余额
4. 有关联记录的账户禁止删除，只能归档
5. 已归档账户默认不出现在“新建记录”账户候选中（可切换查看）
6. 记录编辑允许更换账户，系统需自动重算相关账户余额
7. 汇率换算结果默认预估，允许后续修正为实际金额
8. 对于不允许透支的账户，新增支出/转账前必须校验余额，余额不足时禁止提交
9. 余额不足校验需在前端实时提示并禁用保存按钮，同时提交时再次强校验防绕过

## 6. 界面与交互设计

### 6.1 移动端布局（优先）
1. 底部导航：`首页`、`记录`、`新增`、`账户`、`统计`
2. 首页展示本月汇总卡片 + 趋势图缩略
3. 新增按钮固定在底部中间入口
4. 表单使用单页分组结构，减少弹窗层级
5. 移动端记录列表使用卡片布局，避免横向滚动

### 6.2 桌面端布局
1. 左侧固定导航 + 右侧内容区
2. 记录页支持“列表 + 详情/编辑”双栏布局
3. 统计页支持图表并排展示
4. 左侧导航 Tab 采用统一样式，并对选中态提供明确视觉区分
5. 记录页使用表格布局承载高密度数据，避免长列表导致页面过长
6. 桌面端记录页可使用更宽内容区域以提升表格可读性
7. 桌面端记录页采用全宽内容布局，不使用外层大卡片视觉包裹

### 6.3 关键交互
1. 新建记录时实时展示“预估入账金额”与“预估标记”
2. 记录详情提供“更正实际入账金额”操作
3. 归档账户在账户列表可见，但默认折叠/置底
4. 记录列表中，预估记录在入账金额旁展示小标签“预估”，实际记录不展示标签
5. 新增记录表单按步骤分区：基础信息 -> 金额与币种 -> 汇率 -> 备注与确认
6. 新增记录页在账户未选择或条件不满足时，相关控件保持显示但禁用，并给出提示语；不采用隐藏交互
7. 页面交互不使用 hover 位移动效，避免卡片和按钮在鼠标经过时产生位移
8. 汇率模式使用双选切换组件（自动汇率 / 手动汇率），替代下拉框
9. 页面使用子路由访问，首页 `/home`、记录 `/records`、新增 `/create`、账户 `/accounts`、统计 `/stats`
10. 访问根路径 `/` 时默认重定向到 `/home`
11. 移动端表单需避免横向溢出，不允许页面被输入控件撑宽
12. 记录页支持分页，并允许用户选择每页条数
13. 已删除记录在列表中显示为明显弱化样式并带“已删除”标签
14. 新增记录页选择出账账户后需展示账户关键信息（默认币种、支持币种、透支设置、当前余额）
15. 编辑记录弹窗使用高层级模态层展示，避免页面内联编辑干扰列表浏览
16. 编辑记录遵循与新增记录一致的币种/汇率规则：账户切换后重置币种选择，交易币种命中账户支持币种时锁定同币种入账并跳过汇率
17. 编辑记录中若金额、交易币种、入账币种或汇率变更，保存后需同步更新入账金额与账户余额

## 7. 数据模型设计

### 7.1 实体列表
1. `accounts`
2. `categories`
3. `transactions`
4. `transaction_amounts`

### 7.2 表结构草案（逻辑）

#### accounts
- `id: string`
- `name: string`
- `type: 'cash' | 'debit_card' | 'credit_card' | 'ewallet' | 'other'`
- `baseCurrency: string`
- `allowedCurrencies: string[]`
- `initialBalanceMinor: number`
- `allowOverdraft: boolean`
- `isArchived: boolean`
- `createdAt: string`
- `updatedAt: string`
- `deletedAt: string | null`

#### categories
- `id: string`
- `name: string`
- `kind: 'income' | 'expense'`
- `isSystem: boolean`
- `isArchived: boolean`
- `createdAt: string`
- `updatedAt: string`
- `deletedAt: string | null`

#### transactions
- `id: string`
- `type: 'income' | 'expense' | 'transfer'`
- `fromAccountId: string`
- `toAccountId: string | null`
- `categoryId: string | null`
- `note: string | null`
- `occurredAt: string`
- `createdAt: string`
- `updatedAt: string`
- `deletedAt: string | null`

#### transaction_amounts
- `transactionId: string`
- `originalAmountMinor: number`
- `originalCurrency: string`
- `settledAmountMinor: number`
- `settledCurrency: string`
- `actualSettledAmountMinor: number | null`
- `isEstimated: boolean`
- `fxRate: number | null`
- `fxSource: 'api' | 'manual' | null`
- `fxProvider: string | null`
- `fxTimestamp: string | null`

## 8. 技术方案

### 8.1 技术栈
1. `React + TypeScript + Vite`
2. 状态管理：`zustand`
3. 数据存储：`Dexie (IndexedDB)`
4. 表单与校验：`react-hook-form + zod`
5. 图表：`recharts`
6. 日期处理：`dayjs`
7. UI：先用轻量自定义组件（后续可接入组件库）

### 8.2 架构分层
1. `db`：Dexie schema、迁移、Repository
2. `domain`：业务模型与计算逻辑（余额、统计、汇率处理）
3. `store`：页面状态与交互状态
4. `features`：按模块组织页面与组件（accounts/transactions/stats）
5. `shared`：通用组件、工具函数、常量

### 8.3 推荐目录结构
```text
src/
  app/
    App.tsx
    routes.tsx
  db/
    index.ts
    schema.ts
    seed.ts
    repositories/
  domain/
    accounts/
    transactions/
    stats/
    fx/
  features/
    accounts/
    transactions/
    categories/
    stats/
    settings/
  shared/
    components/
    hooks/
    utils/
    constants/
  store/
    ui.store.ts
    filters.store.ts
```

### 8.4 汇率服务方案
1. 默认 API：Frankfurter（免费、公开）
2. 备用 API：open.er-api（主源失败自动回退）
3. 双源均失败时，提示用户输入手动汇率
4. 记录汇率来源（api/manual 及具体 provider）与时间戳，便于后续追溯

## 9. 响应式实现策略
1. 使用 CSS 断点：
   - `<= 768px` 移动布局
   - `> 768px` 桌面布局
2. 同一页面内容模型不变，仅调整导航与布局结构
3. 表格在移动端改为卡片列表，桌面端使用表格/双栏

## 10. 数据生命周期与软删除
1. 删除记录：设置 `deletedAt`，不物理删除
2. 删除分类：若有关联记录，不允许删除，仅归档
3. 删除账户：若有关联记录，不允许删除，仅归档
4. 查询默认过滤 `deletedAt != null` 项
5. 后续可扩展“回收站恢复”功能

## 11. 验收标准（v1）
1. 用户可完成账户、分类、记录的完整 CRUD 闭环
2. 同币种转账可正确影响两个账户余额
3. 多币种记录可自动换算，并能标记预估与修正实际金额
4. 统计页展示本月汇总、分类占比、按日趋势
5. 移动端与桌面端均可正常使用主要流程
6. 页面刷新后数据仍可从 IndexedDB 正确恢复

## 13. 风险与应对
1. 汇率 API 不稳定：增加手动汇率与错误兜底
2. 多币种统计易混淆：统一按“账户入账币种”统计并明确标识
3. 本地数据一致性：通过事务与集中仓储层保证写入原子性
4. 复杂编辑导致余额错误：采用事件重算策略并加单元测试覆盖
